## How to continue

1. **When a worker ends:** read its `WORKER-REPORT.md` and check its claims against the
   code. Merge its branch into a new branch from `origin/dev`. In a conflict of
   `docs/refactor-17.md`, keep both entries; in a conflict of
   `scripts/layers-ratchet.json`, take one side and run
   `node scripts/check-layers.mjs --update` (or `--init` with the reason in the commit,
   only when a pair has a new name and no import is new).
2. **On the merge, run:** `pnpm install --offline`, the three type checks in
   `services/platform` (`pnpm exec tsrs --noEmit`, `-p tsconfig.tests.json`,
   `-p tsconfig.e2e.json`), `pnpm lint`, `pnpm check:packages`,
   `pnpm --filter @purin-labs/platform test` (baseline 301 files, 1,729 tests) and
   `pnpm portal:build`. After a merge, `lint:layers-page` can ask for
   `node scripts/check-layers.mjs --areas --write`.
3. **Then the full E2E suite**, about one hour:
   `pnpm --filter @purin-labs/platform test:e2e`. Before it: `node scripts/repo-binaries.mjs fetch`,
   `pnpm --filter @purin-labs/async-control build`, `pnpm portal:build`, and the
   variable `PANTRY_ACCOUNT_WORKER_ARTIFACT` (below). The command ends with code 1 when
   a file logs after its teardown; compare the counts of passed files and tests, not the
   exit code. If one journey fails, run it alone three times.
4. **CI checks the merge of `dev` with `main`.** Before a push, make a detached worktree,
   merge `origin/main` into it, and run `pnpm lint:static` and the type checks there.
5. **Ask the owner before each push** to `dev`. Push with
   `git push origin <branch>:dev` when `origin/dev` is an ancestor of the branch.
6. After a push, fix the plan lines that say "on the branch", and refresh the copy of
   the plan in the main checkout.
