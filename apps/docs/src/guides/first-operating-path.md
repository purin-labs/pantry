# First operating path

The product goal is one traceable bakery operating loop, from demand to fulfilled
orders. Fresh counter sales and packaged gift assortments share production and
inventory facts. Japan-to-Singapore export boxes remain an accepted commerce example.

## Accepted foundations

Use the existing café, pâtisserie, pickup, packaged-goods checkout, and export
commerce paths. Kitchen in Purin Pantry separately provides accepted bounded simulation,
saved scenarios, native handling evidence, and governed chat control.

These foundations do not establish a fully automated physical factory. Recipe
work in Plans 61A–E remains draft. Physical robot dispatch remains planned.

## Target operating loop

1. Inspect orders, demand, available lots, ingredients, and packaging stock.
2. Prepare a purchasing or production proposal for an exact quantity and deadline.
3. Bind the recipe revision, equipment, workers, materials, and expected yield.
4. Run the supported simulation and review conflicts, capacity, and uncertain outcomes.
5. Record observed production, accepted yield, rejects, and quality disposition.
6. Release eligible goods for packing. Record packaging consumption and output lots.
7. Allocate saleable stock to counter orders, pickup, gift assortments, or shipments.
8. Reconcile payment, fulfillment, delivery, and customer-service exceptions.
9. Compare saleable yield, waste, labor, packaging, fulfillment costs, and channel sales.

Steps that connect simulated work to actual production need explicit acceptance.
Use the owning commerce operation and its receipt for every inventory or order
change. Preserve operator approval where policy requires it.

## Evidence for an integrated journey

A useful next acceptance scenario is a financier gift order with shared equipment,
rejected pieces, a packaging shortage, and an interrupted agent turn. Preserve
the exact recipe, quantities, grants, approvals, run identity, lots, and receipts.
Recovery must preserve completed work and avoid duplicate stock or payment effects.

Physical measurements must establish yield and packing readiness. A simulated
schedule cannot establish shelf life, physical quality, or a customer delivery promise.
Use [bakery automation](/guides/bakery-automation) for the machine boundary and
[commerce operations](/guides/commerce-operations) for existing commerce behavior.
